# 문제 정확성 감사 보고서

2026-09-12 기준 `npm run audit:problems` 및 `npm run audit:presentation` 결과입니다. 감사는 렌더링 픽셀이 아니라 공통 블록 좌표·투영·층별 표현·채점 함수와 학생 화면에 필요한 증거 표시 계약을 기준으로 수행합니다.

## 검사 범위

- 기본 문제: 1~8차시, 12차시에서 30개
- 생성 연습 문제: 1~8차시, 12차시의 모든 template
- 각 template별 seed 100개
- 총 생성 문제 5,600개
- 검사 항목: 작업판 범위, 공중 블록, 문제 유형과 정답 kind, 개수, 위·앞·옆 투영, 숫자 지도, 층별 표현, 방향 정답의 유일성
- presentation 항목: 3D 모델, 투영·높이 지도·층별 지도 노출 여부, 답안 입력 방식, 실제 격자 행·열, 카메라 정책

## 수정한 오류

1. 2차시 생성기가 뒤·왼쪽을 선택해도 앞·오른쪽 투영을 저장하던 문제를 방향 공통 규칙으로 수정했습니다. 뒤·왼쪽 화면은 가로 방향을 반전합니다.
2. 단일 방향 문제에서 다른 방향과 같은 투영이 나오는 seed를 건너뛰도록 생성기를 수정했습니다.
3. 기본 2차시의 대칭 모양 두 개를 유일한 답을 만드는 비대칭 모양으로 교체했습니다.
4. 자유 쌓기 문제의 사용하지 않는 정답 자료를 빈 블록 정답으로 정리했습니다.
5. 조건 만족형 문제의 `answer`가 투영 조건인 기존 데이터 형식을 감사기가 올바르게 검사하도록 했습니다.

## 결과

```text
기본 문제: 30개 검사
생성 문제: 5,600개 검사
애매한 방향 문제: 0개
문제 감사 통과
```

앞으로 문제 생성기나 기본 문제를 수정할 때도 `npm run audit:problems`와 `npm run audit:presentation`를 실행해야 합니다. 하나라도 실패하면 명령이 실패 상태로 종료됩니다.

## 남은 제한

- 감사는 코드에 정의된 문제와 seed를 검사하며, 운영 Supabase에 교사가 직접 등록한 문제의 내용은 별도 검토가 필요합니다.
- `presentation`은 `shared/problemPresentation.ts`에서 문제 유형·제시 정보·정답 입력을 연결합니다. 운영 DB의 수동 문제도 등록 전에 같은 계약을 만족하는지 검토해야 합니다.
- 2D 격자는 앞/뒤와 왼쪽/오른쪽의 화면 좌우 반전을 포함합니다. 새 투영 로직은 [`shared/spatialConventions.ts`](./shared/spatialConventions.ts)의 함수를 사용해야 합니다.
