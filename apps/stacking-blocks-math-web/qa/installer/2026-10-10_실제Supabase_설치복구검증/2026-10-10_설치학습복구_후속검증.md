## 승인받은 독립 ACL 보존 실험

사용자가 시험 프로젝트에서만 ACL 22개를 과거 기본 권한으로 잠시 변경하고 승인 복구 경로로 되돌리는 작업을 명시적으로 승인했다.

1. 실행 전 합성 데이터만 존재하는지 확인. 모든 원격 SQL 직전 Dashboard URL의 project ref가 시험 ref와 정확히 일치하는지 검사.
2. 앱 22개 테이블 전체 행의 수와 지문, catalog, 직접/유효 권한, default ACL, migration history를 읽기 전용으로 수집.
3. 실제 정상 권한 스냅샷에서 별도의 정확한 원상복구 SQL을 미리 준비했다. 연결/installer 실패 시 동일 시험 Dashboard에서 실행 가능한 대기 절차이며 이번에는 사용할 필요가 없었다.
4. 합성 학급/학생 수와 이름을 다시 확인하는 SQL guard 아래 16테이블·6RPC의 권한만 변경. RLS·함수 본문·데이터·default privileges·migration history는 변경하지 않음.
5. 실제 `/setup`이 `UNRECOGNIZED_SCHEMA`, `history-prefix-24`, **22개 ACL 차이**를 표시.
6. `설치 문제 자동 진단 → 복구 내용 확인`에서 **22개 객체 / 63개 권한 조정** 확인. 승인받은 `복구 승인 및 진행`으로 실행.
7. 설치 완료 24/24, 두 학생 함수 ACTIVE. 읽기 전용 재조회에서 **차이 0 / NO_PERMISSION_DRIFT**.
8. raw catalog와 직접/유효 권한은 최초 스냅샷과 정확히 동일. 22개 테이블의 전체 행 수·지문은 전/중/후 모두 동일. default ACL·migration history도 동일.
9. 새로고침 후 설치 완료 유지. `교사 확인으로 계속`을 눌러 실제 5/8 도착. 권한 오류 재발 없음.

권한 확대 중에는 학습 동작을 수행하지 않고 바로 진단·복구했다. 확대 시간의 정확한 초 단위 측정은 없으므로 수치를 주장하지 않는다. 별도 실패/연결 단절을 의도적으로 주입하지 않았으며, 대기 SQL의 실제 원격 실행도 하지 않았다.

**보존 범위:** 기존 attempt 1, progress 1, reward 1(30 XP·3별), 학생/PIN vault/세션/학급/설정/문제 등 비어 있지 않은 기록을 포함한다. 작품·블록 저장·원답 테이블은 이 비교 시점에 0행이었다. 빈 테이블 동일성을 작품이 들어 있는 보존 검증으로 승격하지 않는다. 복구 뒤의 6블록 활동은 별도 후속 smoke다.

## 검증

- 실패 재현: 기존 build의 새 브라우저 원답 복원 검사에서 DB 기대 답안 대신 빈 배열 → FAIL 확인 후 수정.
- 관련 unit 11 PASS (원답 2, progression 2, resume 7).
- 관련 Chromium 3 PASS: 완료 후 단계 이동·재접속 / 브라우저 context를 새로 만들고 원답 복원·학생 분리 / 저장 503 차단·재시도·숫자 0.
- 실행 코드 `239f3da`: 로컬 typecheck / lint / build PASS, security 1 PASS. CI에서 unit 795/795, Edge/보안/build PASS, PostgreSQL 17.11의 28 profile PASS. 관련 새 브라우저 2건과 progression 1건도 이 정확한 실행 코드의 CI에서 PASS.
- 첫 CI 전체 브라우저는 99 PASS / 1 FAIL. 교사 진도 전용 합성 API가 `progress:save/get`을 구현하지 않아 새 제출 저장을 400으로 거절한 테스트 계약 누락이었다. 이를 SQL 저장/조회로 보완하고 원답 5가 실제 저장되고 재로그인 후 표시되는 assertion을 추가했다. 앱 기대값/완료율/채점 조건은 유지했다. 최종 결과는 이 QA 브랜치의 최신 CI를 함께 확인한다.
- CI 증거: https://github.com/rlasksk030/classgame/actions/runs/37960476618 (첫 1건 실패를 숨기지 않음). 후속 수정은 테스트 어댑터와 문서뿐이며 실행 코드는 동일하다.
- 작업 트리 dependency 읽기 지연으로 동일 lockfile의 임시 검증 checkout을 사용했다. 8개 변경 파일은 소스와 byte-identical 확인. 이것을 별도 실행 코드의 PASS로 재사용하지 않음.
- 로컬 전체 oracle/전체 브라우저는 반복 실행하지 않음. GitHub push 후 CI 상태는 별도로 기록.
- 브라우저 중단: extension timeout → 해당 browser unavailable → native control startup failure. 승인 거부 우회 없음. 반복적인 복구 탐색 중단.
