# 설치 DB 권한 모델과 복구 경계

## 현재 계약

이 모델은 새 권한 정책을 적용하는 migration이 아니다. 원본 migration 24개와 기존 수동 설치 2종으로 만든 **기존 27개 승인 프로필의 유효 권한**을 기록한다. `permission-baseline.json`은 12개 중복 제거 모델로 27개 프로필을 표현하며 원본 migration hash를 대조한다. 원본 catalog, 객체 fingerprint, legacy transaction guard, migration 및 RLS는 변경하지 않았다.

최신 `history-prefix-24`의 권한(소유자 `postgres`):

| 객체 | anon | authenticated | service_role | postgres |
|---|---|---|---|---|
| 기존 테이블 15개¹ | 없음 | SELECT·INSERT·UPDATE·DELETE | SELECT·INSERT·UPDATE·DELETE | 아래 전체 권한 |
| sb_student_sessions | 없음 | 없음 | SELECT·INSERT·UPDATE·DELETE | 전체 |
| Phase 5 테이블 6개² | 없음 | SELECT | 전체 | 전체 |
| sb_owns_class·sb_owns_student·sb_touch_updated_at | EXECUTE (PUBLIC 기본권한) | EXECUTE | EXECUTE | EXECUTE |
| sb_public_class_info | EXECUTE | EXECUTE | 없음 | EXECUTE |
| sb_reset_progress | 없음 | EXECUTE | 없음 | EXECUTE |
| sb_track_challenge_author | 없음 | 없음 | 없음 | EXECUTE |
| 서버 저장/채점 RPC 6개³ | 없음 | 없음 | EXECUTE | EXECUTE |

전체 테이블 권한은 SELECT, INSERT, UPDATE, DELETE, **TRUNCATE**, REFERENCES, TRIGGER, MAINTAIN이다. EXECUTE는 함수 권한이다. `postgres` 소유자는 grant option도 가지고, 위 앱 역할에는 grant option이 없다. anon/authenticated는 superuser·BYPASSRLS가 아니며 service_role은 BYPASSRLS다. PUBLIC 스키마 USAGE와 CREATE도 별도로 대조한다.

1. classes, problems, projects, students, block_snapshots, lesson_settings, student_rewards, challenge_solves, problem_attempts, self_evaluations, student_progress, teacher_settings, shared_challenges, student_pin_vault, worksheet_imports (`sb_` 접두사).
2. project_exports, practice_assignments, peer_problem_attempts, lesson_progress_records, student_created_problems, student_lesson_reflections (`sb_`).
3. sb_set_reward_loadout, sb_reset_class_progress, sb_save_building, sb_submit_challenge, sb_submit_challenge_v2, sb_record_attempt.

기존 수동 설치 프로필에는 anon/authenticated의 TRUNCATE 등 역사적 권한도 있다. 기존에 승인된 프로필을 이번에 새 최소권한 정책으로 몰래 변경하지 않는다. 이를 모든 신규 설치의 정상 권한으로 일반화하지도 않는다.

## 읽기 전용 분류

`permission-audit.sql`은 `pg_class`, `pg_proc`, `pg_roles`, `pg_auth_members`, `pg_namespace`, `pg_default_acl` 및 `has_*_privilege`를 조회한다. 앱 데이터 행이나 비밀값은 조회하지 않는다. 객체 소유자·역할 속성·상속 여부·grant option·스키마 USAGE/CREATE를 확인한다. 기본 grant의 개수는 참고 정보이며 개수만 같다고 정책이 같다고 판정하지 않는다. 역할 상속이 하나라도 있거나 소유자가 다르면 정확한 그래프를 검증하기 전 E다.

| 분류 | 의미 | 이번 처리 |
|---|---|---|
| A_EQUIVALENT | NULL ACL과 명시적 PUBLIC EXECUTE처럼 조회한 역할의 실제 권한이 동일 | 진단만 표시. 기존 fingerprint 불일치 차단 유지 |
| B_BROADER_PERMISSION | 추가 권한 또는 grant option 존재 | 차단 유지 |
| C_MISSING_PERMISSION | 필요한 권한 누락 | 차단 유지 |
| D_STRUCTURAL_CHANGE | 객체·RLS·열·정책·RPC 정의 등 차이 | 차단 유지 |
| E_UNKNOWN | 읽기 실패, 모델 불일치, 상속/소유자 미확정, 권한 증가·감소 혼재 | 차단 유지 |

TRUNCATE는 RLS 행 정책으로 안전해지지 않는다. ALL을 CRUD로 정규화하지 않는다. 새 Supabase default grant와 과거 default grant를 각각 합성 SQL로 재현하며, 16개 table + 6개 RPC 차이가 그대로 차단되는지 확인한다. PostgreSQL 17을 대상으로 하며 MAINTAIN 조회가 불가능한 더 오래된 버전은 읽기 실패/E로 남긴다.

## 실제 PostgreSQL 검증

Mac에서 psql/postgres/Docker가 없으므로 실제 서버 검증은 기존 GitHub Actions의 별도 `Installer native PostgreSQL 17` 작업에 연결했다. 임시 PostgreSQL 17 서비스에서만 27개 프로필 fingerprint와 transaction digest, 17→24 복구 SQL, 재시도 seed 보존, 기존 수동 설치, Supabase ALL defaults와 CRUD opt-out의 22개 차이를 검사한다. 실행 전 CI 전용 플래그·loopback·고정 합성 DB명·빈 DB를 모두 확인한다. 실제 Supabase 또는 교사 DB에 접속하지 않는다. 실행 결과는 해당 CI 결과를 기준으로 판정한다.

로컬 회귀: `tests/installer-permission-audit.test.ts` 및 `tests/installer-supabase-catalog.test.ts` 5/5 PASS. 실제 PostgreSQL CI 결과와 교사 프로젝트 검증은 구분한다.

## 실제 ACL 복구를 허용하기 전

1. 교사 기존 OAuth 세션의 설치 확인으로 현재 catalog와 유효 권한을 읽기 전용 수집한다.
2. 정확한 객체·현재/목표 권한·원인·영향·미확정 역할 상속을 별도 변경 계획으로 표시한다. 관리자 비밀키나 SQL 복사 입력을 요구하지 않는다.
3. 불필요한 권한 회수와 누락 권한 부여 각각의 기능 영향을 검증하고 교사의 명시적 승인을 받는다. 승인 전 grants/revokes는 실행하지 않는다.
4. 향후 실행기는 예상 catalog/effective rights 조건, 트랜잭션 잠금, 10개 보호 테이블 보존 검사, 적용 후 권한/자료 재검사, 실패 rollback을 가져야 한다. 이번 PR에는 실제 ACL 복구 실행기를 넣지 않는다.
5. 실제 학생·PIN·진도·작품·세션·보상과 APP_SESSION_SECRET은 보존한다. 옛 migration 전부 재실행하거나 history를 위조하지 않는다.
