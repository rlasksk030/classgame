## 검증 및 최종 변경

### 결론

진도 계약 수정과 로컬 검증을 마쳤다. 운영 반영은 하지 않았다. 별도 `qa:local`의 기존 실패 때문에 전체 품질 게이트 통과라고 보고하지 않는다.

학생은 필수 확인 문제를 끝내면 완료라고 보지만, 이전 DB 함수는 개념·선택 연습·다른 학생용 생성 문제까지 모두 풀도록 요구했다. 이 불일치가 완료 기록을 막았다. 앞선 `e9b61d4`에서 일반 차시 판정·교사 bulk 집계·10초 갱신을 고쳤으며, 이번 후속 변경은 기존 기록 복구, 활동 참여, 학생 월드, 결과 집계, 초기화까지 같은 계약으로 연결한다.

### 저장과 조회 흐름

1. 일반 차시: 학생 `/lesson/:lesson/solve` → 서버 grader → `sb_record_attempt` → attempt와 progress 같은 트랜잭션 저장 → `lessonCompleted`로 홈/교사/결과 확인.
2. 선택 연습: 동일한 attempt 저장과 보상은 유지하되 필수 분모에서 제외. 홈은 `lessonProblems`와 같은 `practiceDisplaySeed`/`selectPracticeRows`로 현재 세트를 고른다. 교사 선택 연습 수는 과거 세트 포함 완료한 서로 다른 선택 문항 수다.
3. 9차시: `activity:challenge:create`는 참여만 기록. `activity:challenge:attempt` → 서버 채점 → `sb_submit_challenge_v2` → 성공 시 완료. 자기 문제·다른 학급·잠긴 차시 제한 유지.
4. 10·11차시: `activity:project:save`와 기존 `project:save`가 공통 검증을 거쳐 `sb_save_building` 호출. 초안은 참여, 유효한 소개서 제출은 10·11 완료. 기존 완료는 명시적 초기화 전 유지한다.
5. 12차시: 일반 필수 확인 문제와 자기평가는 별도 기록. 자기평가 저장 자체로 필수 완료를 만들지 않는다.
6. 교사: 학급 단위 metadata/attempt/progress bulk 조회 → 진도 요약/상세/수업 결과. 현재 차시는 유효한 최신 학습 시각으로 계산하고 동일 시각만 큰 차시 번호로 정렬한다.
7. 초기화: 교사 인증·학급 소유권 → `sb_reset_class_progress` 단일 RPC → 대상 학생 잠금 → 관련 기록 삭제·보상 재계산. 하나라도 실패하면 모두 rollback. 10·11은 공동 작품이므로 같이 초기화한다.

### 기존 기록과 migration

- 신규: `20261002094201_progress_contract_backfill.sql`, `20261002094642_atomic_progress_reset.sql`. Supabase CLI `migration new`로 생성했다. 기존 migration 수정 없음.
- 앞선 필수 판정: `20261002085049_required_lesson_completion.sql`도 운영 미적용 상태다.
- 운영 aggregate: 일반 완료 복구 2행(2차시 1, 5차시 1), 일반 잘못된 완료를 취소할 대상 0행. 특수 활동 완료 복구 0행. 누락 참여 추가는 9차시 1행·10차시 1행으로, 완료를 부여하지 않는 별도 2행이다. 총 4개 학생×차시 기록이 예상 변경 대상이며 학생 수 4명을 의미하지 않는다. 실행 직전에 다시 집계해야 한다.
- 기존 attempt·오답·XP·별·snapshot·작품·선택 seed를 삭제하거나 재채점하지 않는다. existing progress.updated_at/별도 유지한다. SQL backfill 중 이름이 특정된 timestamp trigger만 트랜잭션/테이블 잠금 안에서 잠시 중지 후 복구한다. RLS 변경 없음.
- 실제 옛 RPC로 만든 미완료 fixture를 복구하고, 보존 대상 테이블/시각의 전후 deep equality와 두 번째 실행 결과 동일성을 검사했다. 손실 0을 로컬 fixture에서 확인했다. 운영은 실행하지 않아 운영 변경도 0이다.
- class reset은 service_role 전용 invoker RPC이며 teacher identity는 인증된 Edge handler에서 전달한다. 학생 목록은 DB가 정한다. 다른 학급 보존, 실패 rollback, 잘못된 범위 거부, anon/authenticated 실행 권한 없음, 10·11 공동 초기화를 검사했다.
- atomic reset은 기존 Phase5 migration이 만드는 테이블도 정리한다. 운영에는 해당 테이블 5개가 없으므로 새 migration만 무작정 적용하면 안 된다. 실제 schema와 23개 파일을 대조하여 필요한 선행 migration을 정리한 뒤 승인된 순서로 적용해야 한다. 빈 migration history에 repair 명령을 자동 실행하지 않았다.
